# Mili AI 팀 생성 및 활동 정의서

> ⚠️ **기획 검토용 초안(Working Draft)**
>
> 본 문서는 최종 기능 명세서가 아니라, 팀 생성 및 활동 기능을 구체화하기 위한 기획 검토용 초안이다.
>
> 작성된 내용은 현재까지 공유된 DB 항목과 기획자의 가설·제안을 바탕으로 정리한 것으로, 운영 정책, 개발 구조, 사용자 권한, 평가 방식에 따라 변경될 수 있다.
>
> 특히 팀 상태값, 상태 전환 조건, 역할별 권한, Git 연동 방식, 평가 기준, 예외 처리 정책은 관련 이해관계자 확인 후 확정이 필요하다.

---

## 1. 문서 목적

본 문서는 Mili AI 플랫폼에서 팀이 생성되고, 구성원이 참여하며, 프로젝트를 수행하고 평가까지 완료하는 전체 흐름을 정리하기 위한 기획 초안이다.

이 문서의 목적은 다음과 같다.

- 현재 확인 가능한 DB 항목을 사용자 플로우와 기능 단위로 해석
- 화면 및 기능 명세 작성을 위한 기초 정책 정리
- 개발·운영·교육 관계자에게 확인이 필요한 항목 식별
- 향후 상태 전이표, 권한표, 예외 처리 정책 수립의 기준 마련

본 문서에 포함된 내용은 아래 네 가지 상태로 구분해 관리한다.

| 상태 | 의미 |
|---|---|
| 🟡 가정 | 현재 기획자가 제안하는 방향 |
| 🔵 확인 필요 | 개발·운영·교육 측 확인이 필요한 내용 |
| 🟢 확정 | 관계자 간 합의가 완료된 내용 |
| 🔴 미정 | 아직 논의되지 않았거나 정책이 없는 내용 |

# 2. 팀 생성 및 구성

## 2.1 팀 생성 주체

### 🟡 가정

현재는 팀 생성 주체로 아래 방식을 고려할 수 있다.

- 학습자가 직접 생성
- 운영자가 생성
- 시스템이 자동 생성

### 🔵 확인 필요

- 실제 팀 생성 주체는 누구인가?
- 프로젝트 유형에 따라 생성 주체가 달라지는가?
- 운영자가 팀을 대신 생성할 수 있는가?
- 시스템 자동 생성 또는 자동 배정 기능이 필요한가?
- 학습자 개인 프로젝트도 내부적으로 팀 데이터로 관리하는가?

## 2.2 팀 생성 시점

### 🟡 가정

팀은 아래 시점 중 하나에서 생성될 수 있다.

- 프로젝트 신청 전
- 프로젝트 신청 후
- 프로젝트 참여 확정 시
- 첫 미션 시작 전

### 🔵 확인 필요

- 팀은 정확히 어느 시점에 생성되는가?
- 프로젝트 신청과 팀 생성 중 어느 단계가 먼저인가?
- 팀이 없는 상태에서도 프로젝트 상세와 미션을 확인할 수 있는가?
- 팀 생성 전 프로젝트 신청을 취소할 수 있는가?

### 🔵 확인 필요

- 최대 인원은 8명으로 고정하는가?
- 인원 미달 상태에서 프로젝트 수행을 시작할 수 있는가?
- 팀 구성 마감 후 인원 추가를 허용하는가?

팀장 지정 방식 예시:

- 최초 생성자 자동 지정
- 팀원 투표
- 운영자 지정
- 시스템 자동 지정

### 🔵 확인 필요

- 팀장 역할은 필수인가?
- 팀장은 누가, 언제 확정하는가?
- 팀장 변경 또는 위임이 가능한가?
- 팀장이 탈퇴하면 새로운 팀장은 어떻게 정하는가?
- 팀장만 최종 제출할 수 있는가?

## 2.6 팀 구성 마감

- 팀 해체 기능이 필요한가?
- 운영자용 팀 관리 화면이 별도로 필요한가?

# 10. 예상 사용자 플로우

> 아래 플로우는 현재 기획자의 제안이며, 실제 운영 정책 확정 후 수정해야 한다.

```text
프로젝트 선택
→ 팀 생성 또는 팀 참여
→ 팀원 모집 및 승인
→ 팀장 확정
→ 팀 구성 완료
→ Git 저장소 연결
→ 첫 미션 시작
→ 프로젝트 수행
→ 최종 결과물 제출
→ 수행완료
→ 평가 시작
→ 모든 평가 완료
→ 평가완료
```

### 🔵 확인 필요

- Git 저장소 연결 시점은 팀 구성 완료 직후가 맞는가?
- 팀 구성 완료 전에 미션을 확인할 수 있는가?
- 평가 시작은 자동인가 운영자 수동인가?
- AI 평가와 동료평가의 순서는 어떻게 되는가?
- 평가 완료 후 결과 수정 또는 이의제기가 가능한가?

# 12. 결론

본 문서는 현재까지 공유된 DB 항목과 기획자의 판단을 바탕으로 작성한 **기획 검토용 초안**이다.

현재 제안하는 기본 흐름은 아래와 같다.

```text
팀 생성
→ 팀 구성
→ 팀 수행
→ 결과물 제출
→ 평가
→ 평가 완료
```

다만 아래 항목은 아직 확정되지 않았으며, 관련 이해관계자 협의가 필요하다.

- 팀 생성 정책
- 팀 구성 정책
- 팀 참여·탈퇴 정책
- 상태 전이 정책
- 역할별 권한
- Git 연동 및 기여율 정책
- 수행완료 기준
- 평가 시작 및 완료 기준
- 재제출·재평가 정책
- 예외 처리 정책
- 운영자 개입 범위

위 항목이 확정되면 본 문서를 기준으로 사용자 플로우, 화면 목록, 기능 명세서, 상태 전이도, 권한표, DB 설계를 구체화한다.
