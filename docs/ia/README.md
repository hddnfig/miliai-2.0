## 2. 해석 규칙

원본이 확정 기획서가 아니므로 모든 항목에 다음 확정도를 적용한다.

| 표기 | 뜻 | 디자인/개발 적용 |
|---|---|---|
| **C** (Confirmed) | 임시 IA에 명시되고 ERD가 뒷받침함 | 바로 설계 가능 |
| **I** (Inferred) | ERD 또는 현재 프로토타입 구조로 합리적으로 예측함 | 가정 표시 후 설계 가능 |
| **P** (Policy needed) | 데이터 구조는 있으나 노출·권한·운영 정책이 미정임 | UI 슬롯만 확보하고 확정 전 개발 보류 |

## 3. 핵심 결론

- 서비스는 **학습자**, **지휘관/교육담당자**, **운영자**의 세 워크스페이스로 분리한다.
- 학습자는 `홈 → 탐색 → 상세 → 수강/참여 → 학습 워크스페이스 → 평가/수료 → 성장`의 한 흐름을 사용한다.
- VOD와 PBL은 목록/상세까지는 공통 탐색 패턴을 쓰되, 학습 이후에는 각각 **플레이어**와 **미션 워크스페이스**로 분리한다.
- AI 교관은 독립 메뉴가 아니라 VOD·PBL 학습 화면에서 호출하는 **공통 우측 패널**로 설계한다.
- 커뮤니티의 `공지/Q&A/FAQ/뉴스`는 하나의 게시판 엔진을 공유하고 게시판 종류만 다르게 표시한다.
- `내 학습`, `성장`, `MY`는 성격이 달라 분리한다. 내 학습은 실행, 성장은 성과 해석, MY는 계정·활동 관리다.
- 운영자 화면은 데이터가 존재하므로 설계 대상에 포함하되, 1차 화면 디자인은 학습자 핵심 흐름을 먼저 진행한다.

## 4. 화면 디자인 권장 순서

```text
공통 Shell
  → 학습자 홈/통합 탐색
  → VOD 목록/상세/플레이어
  → PBL 목록/상세/미션 워크스페이스
  → 내 학습/동료평가/성장
  → 커뮤니티/MY/인증
  → 지휘관
  → 운영자
```

공통 Shell에서 먼저 확정할 항목:

- 역할별 좌측 내비게이션
- 상단 통합 검색, 알림, 프로필, 역할 전환
- 모바일 하단 내비게이션
- AI 교관 패널, 확인 모달, 토스트
- 로딩, 빈 화면, 오류, 권한 없음, 오프라인 상태

## 5. 이번 산출물의 범위

포함:

- 메뉴/기능 구조
- 전체 주요 페이지 목록
- 페이지 목적, 주요 UI 블록, 핵심 기능, 상태
- 화면 간 진입/이탈 연결
- ERD 엔티티와 화면의 근거 연결
- 화면 설계 우선순위와 정책 확인 항목

포함하지 않음:

- 최종 카피와 비주얼 스타일
- 확정 API 명세
- 관리자 권한 매트릭스의 최종 승인
- 실제 URL/API 엔드포인트 구현
- 운영 정책이 필요한 점수·크레딧·수료 기준의 확정
