# 01. 서비스 IA 개요

## 1. 서비스 경계와 사용자

| 사용자 | 핵심 목적 | 기본 진입점 | 근거 | 확정도 |
|---|---|---|---|---|
| 비회원 | 서비스 이해, 콘텐츠 탐색, 가입/로그인 | `/` | 임시 IA의 소개·회원 | C |
| 학습자 | VOD/PBL 학습, 평가, 성장 확인 | `/home` | 임시 IA + 학습/수강 ERD | C |
| 팀 리더/동료평가자 | 팀 구성, 미션 수행, 동료평가 | `/learning` | `tb_team`, `tb_peer_review_*` | C |
| 지휘관/교육담당자 | 부대 참여·성과·지원대상 확인 | `/command` | 현재 프로토타입 + 군부대/계급 ERD | I |
| 운영자 | 콘텐츠·사용자·권한·게시판·시스템 운영 | `/admin` | 임시 IA의 관리시스템 + 다수 운영 엔티티 | C |

지휘관은 독립 회원 종류로 확정된 것이 아니라 `member_role`, `role`, `mil_unit`, `mil_rank`와 현재 프로토타입을 근거로 한 예측이다. 최종 역할 코드는 백엔드와 확인해야 한다.

## 3. 화면 계층 원칙

| 레벨 | 정의 | 예 |
|---|---|---|
| L0 | 워크스페이스 | 학습자, 지휘관, 운영자 |
| L1 | 전역 메뉴 | 학습 탐색, 내 학습, PBL 관리 |
| L2 | 목록/허브 | VOD 목록, 내가 할 평가 |
| L3 | 개체 상세/실행 | VOD 상세, 미션 워크스페이스 |
| L4 | 집중 과업/오버레이 | 퀴즈 풀이, 제출 모달, AI 패널 |

원칙:

- URL을 가져야 하는 화면은 새로고침·공유·뒤로가기가 보장돼야 한다.
- 필터/정렬/탭은 URL query에 반영한다.
- 학습 실행 화면은 일반 Shell을 축소한 집중 모드를 사용하되, 진도와 이탈 경고를 유지한다.
- 생성/수정은 복잡도에 따라 페이지 또는 드로어를 사용한다. 5개 이상의 필드, 파일 업로드, 미리보기가 있으면 페이지를 사용한다.
- 삭제·탈퇴·제출 확정은 확인 모달을 사용하고 결과는 토스트와 화면 상태에 동시에 반영한다.

## 4. URL 규칙

| 유형 | 패턴 | 예 |
|---|---|---|
| 목록 | 복수 명사 | `/vod`, `/projects` |
| 상세 | `/:id` | `/vod/:courseId` |
| 학습 실행 | `/learn` 또는 `/workspace` | `/vod/:courseId/learn/:itemId` |
| 사용자 개인화 | `/me/*` | `/me/learning` |
| 지휘관 | `/command/*` | `/command/unit` |
| 운영자 | `/admin/*` | `/admin/vod/courses` |
| 필터 | query string | `/projects?level=2&status=open` |

기존 프로토타입의 hash route는 탐색용 구현이므로 제품화 시 위 규칙으로 전환한다.

## 5. 메뉴 노출 규칙

- 비회원도 목록과 상세의 일부를 볼 수 있지만 수강/참여/작성 액션에서 로그인을 요구한다. **I**
- 수강이 승인된 학습자만 플레이어와 PBL 워크스페이스에 접근한다. **C**
- 팀 리더 전용 액션은 팀 구성·초대·동료평가 요청이다. **C**
- 지휘관 메뉴는 소속 부대 범위로만 데이터를 제한한다. **I**
- 운영자 메뉴는 `role`, `menu`, `menu_role`에 따라 항목별로 숨김/읽기 전용/편집 가능을 나눈다. **C**
- 콘텐츠 관리자(PBL/VOD)와 회원/게시판/시스템 관리자는 서로의 전용 메뉴에 기본 접근하지 못한다. **C**

## 6. 공통 Shell과 재사용 UI

| 공통 패턴 | 포함 요소 | 사용 화면 |
|---|---|---|
| App Shell | 좌측 메뉴, breadcrumb, 검색, 알림, 프로필 | 로그인 후 전체 |
| 목록 헤더 | 제목, 설명, 결과 수, 검색, 필터, 정렬, 보기 전환 | 모든 카탈로그/관리 목록 |
| 콘텐츠 카드 | 유형, 제목, 난이도, 기간, 상태, 진도, 관심 | 홈/탐색/내 학습 |
| 상태 배지 | 모집, 학습 중, 제출, 평가, 수료, 취소 | VOD/PBL 전체 |
| 단계 진행기 | 현재 단계, 완료 단계, 잠김 단계 | VOD 플레이어/PBL 미션 |
| AI 교관 패널 | 대화, 컨텍스트, 추천 질문, 출처/참고 | VOD/PBL 학습 |
| 파일 블록 | 첨부 목록, 미리보기, 다운로드, 보안 안내 | PBL/게시판/관리자 |
| 평가 폼 | 기준, 점수/선택, 의견, 임시저장, 제출 | 동료평가/퀴즈/역량진단 |
| 데이터 상태 | skeleton, empty, error, permission, offline | 전체 |

## 7. 프론트엔드 구축 우선순위

### P0 — 핵심 학습 수직 슬라이스

1. App Shell, 로그인, 학습자 홈
2. 통합 탐색과 VOD/PBL 목록
3. VOD 상세 → 수강 → 플레이어 → 퀴즈 → 완료
4. PBL 상세 → 참여 → 팀 → 미션 → 제출 → 동료평가
5. 내 학습과 알림

### P1 — 학습 유지와 성과

1. 나의 성장/역량진단/로드맵
2. 커뮤니티
3. 프로필/관심 콘텐츠/활동 내역
4. 지휘관 현황
5. PBL/VOD 콘텐츠 관리자 핵심 CRUD

### P2 — 운영 고도화

1. 전체 운영자 화면
2. 크레딧/상환 정책
3. 수료증 발급/검증
4. 메시지 템플릿/로그/접근 IP/OAuth2

## 8. 디자인 시작 전에 확정할 최소 정책

| ID | 질문 | 미확정 시 처리 |
|---|---|---|
| D-01 | VOD/PBL 열람이 로그인 전 허용되는 범위는 어디까지인가? | 상세 정보만 공개, 학습 액션은 로그인 |
| D-02 | 수강 신청은 즉시 승인인가, 관리자 승인인가? | 상태 UI에 `신청/승인/반려` 모두 준비 |
| D-03 | PBL 팀은 자동 배정, 직접 생성, 초대 중 무엇을 쓰는가? | 세 패턴을 단계 UI로 분리하되 P0는 직접 생성 |
| D-04 | 동료평가 익명 여부와 공개 시점은? | 제출 전 익명, 팀 평가 종료 후 요약 공개 |
| D-05 | 진단 점수로 콘텐츠를 자동 추천하는가? | 추천 사유 슬롯만 만들고 자동화 문구는 보류 |
| D-06 | 크레딧의 사용처와 현금성 여부는? | 잔액/내역만 설계, 상환 UI는 P2 |
| D-07 | 지휘관이 볼 수 있는 개인정보 범위는? | 집계 우선, 개인 상세는 권한 게이트 |
| D-08 | 수료 기준은 차수/과정별 설정인가? | 기준 컴포넌트를 데이터 기반으로 표시 |
