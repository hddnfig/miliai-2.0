# MILI AI 세계관·언어 체계

> 문서 버전: 1.0
> 작성일: 2026-07-24
> 역할: 브랜드 세계관, 명칭, 용어, UX 라이팅, 시각 원칙의 단일 기준

## 1. 세계관 한 문장 정의

**MILI AI는 현실의 문제에서 발견한 가능성을 지식·AI·협력으로 해석하고, 각자의 결과물로 미완성의 영역을 함께 완성해 가는 학습 세계다.**

## 2. 소개 문안

### 2.1 100자 내외

현실의 문제는 아직 해석되지 않은 가능성의 영역으로 나타납니다. 학습자는 지식과 AI, 동료의 관점을 연결해 해답을 만들고, 그 결과를 모두의 성장 흔적으로 남깁니다.

### 2.2 300자 내외

MILI AI의 세계는 현실에서 마주한 문제와 가능성이 빛, 선, 흐름, 구조로 나타나는 미완성의 장입니다. 학습자는 지식을 익히고 프로젝트의 미션을 수행하며 흩어진 단서를 연결합니다. AI 교관은 정답을 대신 주는 존재가 아니라 질문을 정교하게 만들고 근거를 찾도록 돕는 안내자입니다. 동료의 서로 다른 관점은 혼자 보지 못한 구조를 드러냅니다. 제출하고, 피드백을 받고, 다시 개선한 결과물은 사라지지 않고 역량의 근거와 다음 학습자의 길이 됩니다.

### 2.3 약 700자 전체 스토리

현실에는 이미 답이 정해진 문제보다 아직 충분히 해석되지 않은 문제가 더 많습니다. 사람들의 질문과 시도, 지식의 조각이 쌓이면서 그 가능성들은 보이지 않는 하나의 장을 이루었지만, 서로 연결되지 못한 채 미완성의 영역으로 남았습니다. MILI AI는 이 영역을 발견하고 작동시키기 위해 만들어진 학습의 세계입니다.

학습자는 관찰자로 머물지 않습니다. 자신의 임무와 관심에서 출발해 필요한 지식을 익히고, 프로젝트를 선택하며, 단계별 미션으로 문제를 작게 나눕니다. AI 교관은 모든 답을 대신 만드는 지휘자가 아니라 질문의 맥락을 읽고 단서와 근거, 다음 탐색 방향을 비추는 안내자입니다. 학습자가 판단하고 책임지는 구조는 그대로 유지됩니다.

하나의 관점만으로는 미완성 영역의 전체 구조를 볼 수 없습니다. 동료의 질문, 평가, 피드백은 흩어진 선을 연결하고 놓친 조건을 드러냅니다. 제출은 끝이 아니라 현재의 해석을 세상에 드러내는 순간이며, 수정과 재제출을 통해 결과는 더 선명해집니다. 완성된 결과물은 개인의 포트폴리오에 남는 동시에 역량을 증명하는 근거가 되고, 허용된 범위에서 다음 학습자가 참고할 수 있는 길이 됩니다.

학습이 이어질수록 개인의 역량 지도에는 새로운 연결이 생기고, 팀과 부대에는 함께 해결할 수 있는 문제의 범위가 넓어집니다. 이 세계의 최종 모습은 모든 공간이 고정된 완성품이 되는 것이 아닙니다. 새로운 문제가 나타날 때마다 누구나 학습하고 협력하며 더 나은 해석을 축적할 수 있는, 계속해서 완성되어 가는 살아 있는 지식 기반이 되는 것입니다.

## 3. 스토리 구조 10요소

| 요소 | 서비스용 정의 |
|---|---|
| 세계의 탄생 | 현실의 질문·시도·지식이 모여 가능성의 장을 형성했다. |
| 미완성의 이유 | 문제의 맥락과 지식이 흩어져 있고 아직 충분히 연결·검증되지 않았다. |
| 학습자의 참여 | 자신의 현장 문제를 더 나은 방식으로 해결하고 그 근거를 남기기 위해 참여한다. |
| AI 교관의 역할 | 질문을 구조화하고 관련 근거와 다음 행동을 비추는 안내자다. 정답·판단·책임을 대체하지 않는다. |
| 프로젝트의 의미 | 미완성 영역 하나를 현실의 해결 과제로 구체화한 학습 단위다. |
| 미션의 의미 | 복잡한 문제를 관찰·해석·구현·검증의 단계로 나눈 실행 단위다. |
| 협력의 이유 | 서로 다른 경험과 관점이 연결되어야 숨은 조건과 더 나은 해법이 드러난다. |
| 결과물의 변화 | 결과물은 영역을 활성화하는 흔적이자 재사용 가능한 문제 해결 근거가 된다. |
| 역량 축적 | 완료 횟수가 아니라 결과물·평가·개선 이력에 연결된 증거로 축적된다. |
| 최종 상태 | 정적인 완성 세계가 아니라 새 문제에 대응해 계속 확장되는 공동 지식 기반이다. |

## 5. 온보딩·전환 스토리

### 5.1 온보딩 4단계

1. **발견** — “현실의 문제에는 아직 드러나지 않은 가능성이 있습니다.”
2. **연결** — “지식과 AI, 동료의 관점을 연결하면 문제의 구조가 선명해집니다.”
3. **완성** — “프로젝트와 미션으로 해법을 만들고, 피드백으로 더 나아지게 하세요.”
4. **축적** — “당신의 결과물은 역량의 근거가 되고 다음 가능성을 여는 길로 남습니다.”

### 5.2 주요 메시지

| 위치 | 문구 |
|---|---|
| 메인 화면 | 오늘 연결할 지식이, 내일 해결할 문제의 길이 됩니다. |
| 프로젝트 시작 전 | 이 프로젝트는 하나의 정답을 찾는 과정이 아닙니다. 조건을 해석하고, 근거를 연결해, 실행 가능한 결과를 만드세요. |
| 프로젝트 완료 | 하나의 영역이 더 선명해졌습니다. 남긴 결과와 개선의 기록이 새로운 역량의 근거가 됩니다. |

## 6. 용어 설계 원칙

- L1 기능 중심: 행동·거래·오류·권한처럼 즉시 이해해야 하는 곳. `학습`, `제출`, `평가`를 사용한다.
- L2 혼합: 기능과 브랜드 경험을 함께 전달하는 곳. `성장 기록`, `역량 지도`, `미션 흐름`을 사용한다.
- L3 세계관 중심: 온보딩·배너·빈 상태·완료·성취 연출. 기능 설명 또는 CTA를 반드시 함께 둔다.
- 실제 군 계급을 레벨·랭크로 사용하지 않는다.
- 전투·정복·공격·파괴·승패를 성장 은유로 사용하지 않는다.
- 하나의 개념은 한 표기를 기본으로 하고 세계관 후보는 카피·그래픽 보조에만 쓴다.

## 9. UX 라이팅 원칙

1. 제목은 현재 상태, 본문은 이유와 다음 행동, CTA는 동사로 쓴다.
2. 세계관 문장 뒤에는 실제 기능·조건·기한을 둔다.
3. AI의 답은 제안이며 검증이 필요하다고 알리고 출처·불확실성을 표시한다.
4. 오류는 사용자의 탓으로 쓰지 않고 보존된 내용과 복구 방법을 먼저 알린다.
5. `실패`보다 `보완 필요`, `정복`보다 `완료`, `랭킹`보다 `참여 현황`을 우선한다.

| 배경 | 저대비 레이어와 넓은 여백. 콘텐츠 가독성보다 앞서지 않음 |
| 카드·패널 | 반투명 남용 없이 면과 얇은 연결선으로 구조 표현 |
| 진행률 | 퍼센트와 완료 수를 기본으로, 선이 연결되거나 면이 선명해지는 보조 연출 |
| 미션 연결 | 순서·분기·잠금 이유가 읽히는 노드/리스트 이중 표현 |
| 잠금·해금 | 회색화만 하지 않고 잠금 아이콘·이유·충족 행동 제공 |
| 완료 | 과도한 폭발 효과 없이 색·선·미세 파동으로 안정적인 활성화 표현 |
| 역량 | 레이더 차트 단독 사용을 피하고 역량명·수준·근거·최근 갱신을 병기 |
| 성장 | 단순 누적 점수보다 사건과 증거가 연결된 타임라인 사용 |
| 팀·동료 | 개인 노드 사이의 상호 연결과 기여를 표현하되 서열형 피라미드 지양 |
| AI 교관 | 인격화 캐릭터보다 따뜻한 빛의 커서·파동·레이어로 표현. AI 표식 명시 |
| 움직임 | 상태 변화에만 150–400ms 사용, `prefers-reduced-motion` 지원 |
| 모바일 | 배경 입자·동시 노드를 줄이고 리스트와 수치 우선 |
| 접근성 | WCAG 2.2 AA 목표, 색 외 상태 단서, 본문 대비, 키보드·스크린리더 지원 |

## 12. 시각 방향 3안

| 방향명 | 설명 | 키워드 | 대표 그래픽 | 적합 화면 | 장점 | 위험 요소 | 난이도 |
|---|---|---|---|---|---|---|---|
| A. 빛의 지형 | 흐릿한 등고 레이어가 학습에 따라 선명해지는 방향 | 발견, 지형, 층, 선명함 | 등고선, 부드러운 광점, 활성 면 | 홈, 프로젝트, 성장 지도 | 탐색과 완성 서사가 직관적 | 지도·영토·정복 이미지로 흐르지 않게 언어 통제 | 중 |
| B. 연결의 직조 | 점과 선, 얇은 띠가 지식·사람·결과를 엮는 방향 | 연결, 협력, 흐름, 축적 | 연결망, 리본, 교차점, 파동 | 팀, 동료평가, AI 교관, 로드맵 | 관계와 지식 연결 표현에 강함 | 복잡하면 군사 HUD·네트워크 모니터처럼 보임 | 중상 |
| C. 결정의 형성 | 반투명 조각과 면이 정렬되어 하나의 구조가 되는 방향 | 해석, 정제, 근거, 완성 | 결정면, 모듈 조각, 층진 패널 | 미션, 제출, 피드백, 성취 | 결과 개선과 버전 변화를 잘 표현 | 과도한 3D·유리 효과는 가독성과 성능 저하 | 상 |

최종 권장 조합은 A를 기본 환경, B를 연결·협업, C를 완료·성취 순간에 제한적으로 사용하는 것이다. 세 방향을 화면마다 무작위로 섞지 말고 의미에 따라 역할을 고정한다.
